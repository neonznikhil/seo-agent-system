================================================================================
RANKFORGE — AUTONOMOUS SEO AGENT SYSTEM
Complete Feature Breakdown, Agent Roles, Working Components & Testing Checklist
================================================================================

PROJECT OVERVIEW
================================================================================
Name:        RANKFORGE
Type:        Autonomous SEO + GEO/AEO (Generative Engine / Answer Engine Optimization)
Stack:       Python (FastAPI Backend) + Next.js (Frontend) + Supabase (Database)
AI Engine:   CrewAI Agents + NVIDIA NIM LLMs (meta/llama-3.1-70b-instruct)
Purpose:     Optimize websites for both Google Search rankings AND AI/LLM citation
             (ChatGPT, Perplexity, Google AI Overviews)

CORE VALUE PROPOSITION:
Unlike traditional SEO tools that only track rankings, RANKFORGE uses autonomous
AI agents to:
  1. Audit sites for SEO + AI-visibility issues
  2. Write human-quality content optimized for Google AND AI citation
  3. Monitor competitors, backlinks, and technical health 24/7
  4. Push approved content to WordPress — but ONLY after human approval

LIGHTWEIGHT DEPLOYMENT (NO DOCKER)
================================================================================
Requirements:
  - Python 3.8+  |  Node.js 16+  |  Supabase account (free tier OK)
  - NVIDIA API key (NIM — free tier available)
  - Firecrawl API key (free tier available — for competitor/browser tools)
  - Redis (optional — system works without it with warning logs)
  - WordPress site (optional — works in preview-only mode without it)

Setup Steps:
  1. python -m venv venv && venv\Scripts\activate
  2. pip install -r requirements.txt
  3. cd frontend-next && npm install
  4. Copy .env.example to .env and fill in API keys
  5. Run Supabase SQL schemas (in order):
       supabase_schema.sql
       supabase_schema_v2.sql
       supabase_schema_enhanced.sql
       supabase_schema_agents.sql
  6. Start backend:  uvicorn backend.main:app --reload --port 8000
  7. Start frontend: cd frontend-next && npm run dev -- --port 3000
  8. Open browser:  http://localhost:3000
  9. Health check:  http://localhost:8000/health

PART 1: HOW EACH AGENT WORKS
================================================================================
There are 6 CrewAI Agents defined in backend/agents/crew.py, orchestrated in a
SEQUENTIAL process. Each agent has a specialized persona, specific tools, and
hard-coded safety rules.

All agents use the same NVIDIA NIM LLM:
  Model: meta/llama-3.1-70b-instruct
  Wrapper: NIM_LLM class in crew.py calls database.call_nim_llm()

--------------------------------------------------------------------
AGENT 1: AUDITOR AGENT
--------------------------------------------------------------------
Persona:    Senior SEO, AEO & GEO Auditor
Role:       Find every ranking-blocking, featured-snippet-blocking, and
             AI-rendering issue on the website. Prioritize fixes by AI visibility impact.
Goal:       Identify and prioritize ALL SEO/AEO/GEO issues

BACKSTORY / MINDSET:
  - 10-year SEO/GEO expert obsessed with AI-powered visibility
  - Assumes every site is broken in Google Search OR AI summaries
  - Measures impact in organic traffic AND AI-generated responses
  - Never approves content without E-E-A-T signals or structured data
  - Prioritizes: 1) Featured snippet opportunities, 2) AI/LLM rendering quality,
    3) Traditional SEO issues

TOOLS USED:
  - ThinkAndLogTool     -> Logs thoughts/decisions to agent_thoughts table
  - CrawleeTool         -> Browser-based crawling (up to 50 pages)
  - SEOAEOGEOTool       -> Combined SEO/AEO/GEO analysis per URL
  - SERPAnalyzerTool    -> Keyword SERP analysis, feature extraction

WHAT IT DOES (TASK DESCRIPTION FROM CREW.PY):
  1. Crawls up to 50 pages where last_audited > 7 days AND impressions > 100
  2. Uses seo_aeo_geo_tool to identify:
       a) Traditional SEO issues (meta tags, titles, links, headers)
       b) Featured snippet opportunities (answer blocks, tables, lists)
       c) AI/LLM visibility barriers (missing schema, poor structure)
  3. Uses serp_analyzer_tool for keyword SERP analysis
  4. Calculates AI impact score = impressions * (3 - CTR)
  5. Logs top 10 issues by AI visibility impact via think_tool
  6. Saves issues to audits table with status=pending_approval

SAFETY RULES (HARD-CODED IN BACKSTORY):
  You are NEVER allowed to call publish or update WordPress directly.
  You only propose issues. Publishing requires human approval via dashboard.
  Your job is RESEARCH AND PROPOSAL ONLY - never execution.

OUTPUT:
  - audits table entries (up to 10 prioritized issues)
  - agent_thoughts log entries
  - CREWAI_AUDIT.md file with full audit results

STATUS AFTER RUN:  Creates proposals for the EDITOR to act on

AGENT 3: WRITER AGENT (MOST COMPLEX)
--------------------------------------------------------------------
Persona:    AI-First SEO Content Strategist
Role:       Create content that ranks in Google AND gets cited by AI assistants
             (ChatGPT, Google AI, Claude). Focus on E-E-A-T, featured snippets,
             and LLM rendering.
Goal:       Generate up to 2 human-quality, AI-optimized blog post drafts per kickoff

TOOLS USED:
  - ThinkAndLogTool           -> Reasoning logs
  - QualityGateTool           -> Pre-publish quality checks
  - LlmsTxtTool               -> llms.txt generation
  - CrawleeTool               -> Site crawling for context
  - VectorMemoryTool          -> Duplicate detection via vector similarity
  - KnowledgeExtractorTool    -> Extract facts from crawled content
  - ToneAnalyzerTool          -> Match brand writing style
  - SEOAEOGEOTool             -> Final optimization scoring
  - ContentOptimizerTool      -> Content quality optimization

WHAT IT DOES (DETAILED PIPELINE):
  Phase 1 - AUDIENCE & DEMAND:
    - Fetches active keywords from GSC (impressions > 500, CTR < 3%)
    - Maps keywords to business use cases
    - Analyzes search intent per keyword

  Phase 2 - SERP & COMPETITORS:
    - Fetches top 10 Google results for target keyword
    - Analyzes content depth and structure of competitors
    - Identifies content gaps
    - Verifies facts against first-party data

  Phase 3 - POSITIONING & OUTLINE:
    - Generates unique angle/title
    - Creates H2/H3 structure
    - Plans internal links (3+ to high-traffic pages)
    - Creates E-E-A-T plan (author bio, dates, reviewer)
    - Plans schema markup (FAQ, HowTo, Article)

  Phase 4 - MULTI-STEP WRITING (1500-2000 words):
    - 50-word direct answer (featured snippet target)
    - Data table (comparison/specs)
    - Detailed explanations with statistics
    - 5+ FAQ section (PAA optimization)
    - Internal links throughout
    - Brand tone applied
    - Humanization rules enforced

  Phase 5 - MULTI-EXPERT REVIEW (11 experts):
    - SEO Expert, EEAT Expert, Helpful Content, AI Search, Brand Voice,
      Business Impact, Editorial, Fact Check, Internal Link, Citation, Humanizer

  Phase 6 - HUMANIZER & GATE:
    - Runs QualityGateTool (tone match >= 0.75, spell errors < 3)
    - Checks vector memory for duplicates (blocks if similarity > 0.85)
    - Sets status = pending_approval
    - NEVER sets status to published

SAFETY RULES:
  CRITICAL - You never publish blogs or update pages.
  You create content with status pending_approval via propose_blog tool.
  Publishing is FORBIDDEN - only human can approve via dashboard.
  If you attempt to publish directly, safety gate will BLOCK you and log CRITICAL ERROR.

OUTPUT:
  - content_log entry with status=pending_approval
  - content_pipeline_logs (100+ step audit trail)
  - content_expert_reviews (11 expert scores 0-100 each)
  - Full blog content with FAQ, tables, internal links
  - Quality check results

STATUS AFTER RUN:  Draft created, awaiting human approval

AGENT 4: TECH SEO AGENT
--------------------------------------------------------------------
Persona:    AI-Ready Technical SEO Specialist
Role:       Ensure site structure, schema, and performance enable both Google
             crawling AND AI agent extraction. Optimize for Core Web Vitals +
             LLM accessibility.
Goal:       Run technical SEO and AI-readiness checks

TOOLS USED:
  - ThinkAndLogTool    -> Logs technical findings
  - CrawleeTool        -> Crawls site for technical issues
  - SEOAEOGEOTool      -> AI-readiness assessment

WHAT IT CHECKS:
  1. sitemap.xml  — exists, valid, submitted to GSC
  2. robots.txt   — allows crawling of important pages
  3. Canonical tags — no duplicates, self-referencing
  4. Broken links  — 404 errors from crawl
  5. 404 pages     — proper handling or redirects
  6. Redirect chains — max 3 hops
  7. Schema markup — FAQ/HowTo present, valid JSON-LD
  8. Core Web Vitals:
       - LCP (Largest Contentful Paint) < 2.5s
       - FID (First Input Delay) < 100ms
       - CLS (Cumulative Layout Shift) < 0.1
  9. LLM accessibility — clear structure, entity markup, passage indexing ready

SAFETY RULES:
  You never update robots.txt or sitemap directly. Only propose changes.

OUTPUT:
  - technical_audits table entries (with AI-readiness score)
  - agent_thoughts entries

STATUS AFTER RUN:  Technical issues logged for human review

PART 2: HOW THE AGENTS WORK TOGETHER (CREW WORKFLOW)
================================================================================
SEQUENTIAL PROCESS (defined in crew.py -> plan_blogs_for_website):

  Auditor -> Editor -> Writer -> Tech SEO -> Backlink -> Manager

  Auditor:   Crawls site, finds issues, calculates AI impact scores
  Editor:    Plans content strategy, proposes page-level fixes
  Writer:    Generates blog drafts (up to 2 per kickoff)
  Tech SEO:  Runs technical audits, AI-readiness checks
  Backlink:  Analyzes backlink profile for AI citation potential
  Manager:   Prioritizes all work by AI visibility impact, manages queue

SHARED TOOLS (used by multiple agents):
  - ThinkAndLogTool:       All agents (reasoning logs)
  - CrawleeTool:           Auditor, Writer, Tech SEO (site crawling)
  - SEOAEOGEOTool:         Auditor, Tech SEO, Backlink (analysis)
  - VectorMemoryTool:      Writer, Auditor (duplicate detection)
  - QualityGateTool:       Writer only (pre-publish checks)
  - KnowledgeExtractorTool: Writer only (fact extraction)
  - ToneAnalyzerTool:      Writer only (brand voice matching)
  - LlmsTxtTool:           Writer only (llms.txt generation)
  - SERPAnalyzerTool:      Auditor only (SERP analysis)
  - ContentOptimizerTool:  Writer only (content quality)

SHARED SAFETY RULES (enforced in all agent backstories):
  1. NO agent may publish or update WordPress directly
  2. NO agent may disavow backlinks
  3. NO agent may update robots.txt or sitemap
  4. ALL publishing actions require X-User-Id header (human approval)
  5. Safety gate logs CRITICAL ERROR if agent attempts unauthorized action

PART 8: KEY SAFETY RULES SUMMARY
================================================================================
1. NO AGENT CAN PUBLISH DIRECTLY
   - All agents have SAFETY RULE in their backstory
   - Writer creates drafts with status=pending_approval
   - Agents lack WordPress publish permissions in their tool access

2. HUMAN APPROVAL REQUIRED (X-User-Id)
   - All publish endpoints require X-User-Id header
   - Missing header -> 403 Forbidden
   - Header is logged in critical_action_logs

3. RATE LIMITING
   - Max 5 approvals per minute per website
   - Prevents accidental mass publishing

4. HOMEPAGE PROTECTION
   - Homepage edits require confirm_homepage=true
   - Extra confirmation dialog in frontend

5. SAFETY GATE LOGS EVERYTHING
   - critical_action_logs table records:
     * All blocked attempts
     * Successful approvals
     * Agent name, action, user_id, timestamp

6. DRAFT-ONLY FROM AGENTS
   - Agents can only create WordPress drafts
   - Publishing is exclusively human-triggered
   - WordPressService.draft_post() sets status=draft
   - WordPressService.publish_post() requires user_id
